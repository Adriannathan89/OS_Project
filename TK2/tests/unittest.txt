UNIT TEST / SKENARIO PENGUJIAN MULTILEVEL QUEUE
==============================================
I/O pada dokumen ini berarti input/output terminal sesuai scheduler.c.
Tidak ada input durasi I/O perangkat atau status blocked.
Berkas input .txt hanya berisi bilangan, sehingga bisa langsung dialihkan
ke stdin. PID mengikuti urutan baris input, mulai dari P1.

CARA MENJALANKAN (dari direktori TK2)
  gcc -std=c11 -Wall -Wextra -Wpedantic scheduler.c -o /tmp/tk2-scheduler
  /tmp/tk2-scheduler < tests/inputs/01_normal_q1.txt
  Ulangi perintah kedua untuk setiap berkas input yang tercantum di bawah.
  Untuk menjalankan semuanya:
  for input in tests/inputs/*.txt; do
    printf '\n%s\n' "$input"
    /tmp/tk2-scheduler < "$input"
  done

FORMAT INPUT
  Baris 1: jumlah proses (N)
  Baris 2: quantum Q1
  Baris 3: quantum Q2
  N baris berikutnya: AT BT queue
  Q1 dan Q2 menggunakan RR; Q3 menggunakan FCFS.
  Prioritas diwakili queue, bukan kolom priority terpisah.

ATURAN UNTUK HASIL MLQ YANG DIHARAPKAN
  Q1 > Q2 > Q3; queue lebih tinggi mempreempt queue lebih rendah.
  Proses tetap di queue awal (MLQ, bukan MLFQ).
  Arrival bersamaan dimasukkan sesuai urutan PID.
  RR yang habis quantum dimasukkan ke belakang pada akhir tick; arrival
  pada waktu berikutnya masuk setelah proses yang direqueue tersebut.
  Preemption dari queue atas mengembalikan proses ke depan queue asal.
  Quantum dimulai ulang saat dipilih, sesuai rr_start() di scheduler.c.
  Q3 menjalankan proses sampai selesai kecuali dipreempt queue atas.
  Interval Gantt menggunakan [mulai, akhir); biaya context switch = 0.
  Start = waktu pertama mendapat CPU; CT = completion time.
  TAT = CT - AT; WT = TAT - BT; RT = Start - AT.

BATAS IMPLEMENTASI DAN KRITERIA LULUS
  main() saat ini mencetak konfigurasi seluruh proses, tetapi hanya
  memanggil simulate_fcfs(&queue_list[2]). Dispatcher MLQ belum dipanggil.
  Karena itu hasil MLQ di bawah adalah target pengujian, bukan klaim bahwa
  scheduler.c sudah menghasilkan hasil tersebut. Q1/Q2 belum dijalankan.
  Program juga belum mencetak tabel CT/TAT/WT/RT atau rata-ratanya.
  Lulus penuh: semua proses dijadwalkan dan interval/angka cocok dengan
  hasil yang diharapkan. Exit code 0 saja tidak cukup untuk lulus.
  TC08 dapat diverifikasi melalui interval Q3 yang sudah dicetak program;
  tabel metrik TC08 dihitung manual dari interval tersebut.

DATA INPUT
  Seluruh data dibuat khusus untuk pengujian ini. Perbandingan quantum
  memakai kumpulan proses yang sama di TC01, TC02, TC03, sehingga hanya
  quantum yang berubah. Lima kategori wajib dicakup oleh TC01-TC07;
  TC08 merupakan tambahan khusus verifikasi manual.

PERHITUNGAN MANUAL TC08 (UNTUK LAPORAN)
=====================================
Semua proses berada di Q3, sehingga FCFS dapat diverifikasi pada program
saat ini. Tidak ada proses Q1/Q2 yang dapat melakukan preemption.

1. P1 datang t=0, berjalan 0 sampai 3 (BT=3).
2. P2 datang t=1, menunggu P1 selesai, berjalan 3 sampai 5 (BT=2).
3. CPU idle 5 sampai 6 karena P3 dan P4 baru datang t=6.
4. P3 dan P4 datang bersamaan. Urutan input P3 lebih dahulu, sehingga
   P3 berjalan 6 sampai 7 (BT=1), lalu P4 berjalan 7 sampai 11 (BT=4).
5. CPU idle 11 sampai 15; P5 berjalan 15 sampai 17 (BT=2).

PID  CT  TAT = CT-AT    WT = TAT-BT    RT = Start-AT
P1    3    3-0  = 3       3-3 = 0       0-0   = 0
P2    5    5-1  = 4       4-2 = 2       3-1   = 2
P3    7    7-6  = 1       1-1 = 0       6-6   = 0
P4   11   11-6  = 5       5-4 = 1       7-6   = 1
P5   17   17-15 = 2       2-2 = 0      15-15  = 0

Rata-rata TAT = (3+4+1+5+2)/5 = 15/5 = 3.00
Rata-rata WT  = (0+2+0+1+0)/5 =  3/5 = 0.60
Rata-rata RT  = (0+2+0+1+0)/5 =  3/5 = 0.60
Total BT = 12; total idle = 1+4 = 5; waktu selesai terakhir = 17.

Bagian output interval program yang wajib identik:
P1: 0 -> 3
P2: 3 -> 5
P3: 6 -> 7
P4: 7 -> 11
P5: 15 -> 17

Output program saat ini menampilkan interval di atas, bukan metrik.
